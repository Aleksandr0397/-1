# Бот для Мосбиржи и песочницы Т‑Инвестиций

Рабочая первая версия на Python 3.11+: загрузка дневных свечей, бэктест и автоматические заявки в **песочнице на виртуальные деньги**. Стратегия — SMA(20/60) для одной рублёвой акции на TQBR, без плеча и коротких позиций. Прибыльность этой стратегии пока не подтверждена.

Зависимости для запуска — только стандартная библиотека Python. Команды ниже выполняются из каталога проекта на Linux/macOS. В Windows для `zoneinfo` может потребоваться пакет `tzdata`.

## Быстрый запуск без токена

```bash
cd /workspace/moex-bot
python -m moex_bot demo
python -m unittest discover -s tests -v
```

`demo` использует искусственные цены и проверяет работоспособность. Результаты сохраняются в `reports/demo/summary.json`, `trades.csv`, `equity.csv`. Доходность демо не имеет отношения к реальному рынку.

## Реальные исторические данные

```bash
python -m moex_bot download --ticker SBER --from 2023-01-01 --to 2024-12-31 --out data/sber-2023-2024.csv
python -m moex_bot backtest --csv data/sber-2023-2024.csv --lot 10 --out reports/sber-2023-2024
```

Источник по умолчанию — публичный MOEX ISS, торговая доска TQBR. Текущий московский день исключается. CSV содержит `time,open,high,low,close,volume`; время включает часовой пояс. Метаданные источника лежат рядом в `.meta.json`.

`--lot` требуется явно: **текущий размер лота не означает исторический размер лота**. В примере принят постоянный лот 10 для всего тестового периода; это предположение нужно сверять для выбранного инструмента и дат. Период с изменением лота следует разделить. История корпоративных действий и лотов автоматически не загружается.

Опции бэктеста:

```bash
python -m moex_bot backtest --csv data/sber-2023-2024.csv --lot 10 \
  --capital 100000 --fast 20 --slow 60 --allocation 0.2 --drawdown 0.1 \
  --commission 0.0005 --slippage 0.001 --out reports/custom
```

Все доли задаются числом от 0 до 1: `0.0005` = комиссия 0,05% на каждой стороне; `0.001` = проскальзывание 0,1%. Ставки по умолчанию — параметры модели, а не сведения о вашем тарифе. Выставьте свои расходы.

Проверенный прогон SBER, 510 свечей за 2023–2024 годы: при капитале 100 000 ₽ и доле позиции 20% получилось +3,95%, максимальная наблюдаемая просадка 2,89%, 6 сделок. Покупка и удержание с той же начальной долей дали +5,56%. Это ценовой расчёт без дивидендов, налогов и корпоративных действий, с постоянным предполагаемым лотом. Он не доказывает преимущества стратегии; параметры не подбирались по этому периоду.

## Песочница Т‑Инвестиций

Получите токен для песочницы в [документации Т‑Инвестиций](https://developer.tbank.ru/invest/intro/intro). Задайте `TINVEST_SANDBOX_TOKEN` локально. Токен не нужно присылать в чат. Пример ввода без записи значения в историю bash:

```bash
read -rs -p 'Sandbox token: ' TINVEST_SANDBOX_TOKEN
export TINVEST_SANDBOX_TOKEN
```

Создайте отдельный виртуальный счёт и сохраните его идентификатор из ответа:

```bash
python -m moex_bot sandbox-init --cash 100000
python -m moex_bot sandbox-accounts
```

Проверьте план действий — по умолчанию заявки не отправляются:

```bash
python -m moex_bot sandbox-step --account ACCOUNT_ID --ticker SBER --state state/sber.sqlite
```

Однократное исполнение в песочнице:

```bash
python -m moex_bot sandbox-step --account ACCOUNT_ID --ticker SBER --state state/sber.sqlite --submit
```

Непрерывный запуск с проверкой каждые пять минут:

```bash
python -m moex_bot sandbox-run --account ACCOUNT_ID --ticker SBER --state state/sber.sqlite --interval 300 --submit
```

Остановка — Ctrl+C. При ошибке чтения бот завершает цикл с ошибкой. При неопределённом результате отправки он сохраняет UUID заявки и ждёт её подтверждения, продолжая сверку при следующих шагах. Автоматического повторного отправления такой заявки нет. При сообщениях `pending_order_uncertain` или `submission_uncertain` проверьте заявку в песочнице; удаление состояния может привести к повторной торговле.

Используйте один выделенный счёт, один тикер и **один постоянный путь состояния**. Внутри одного пути процессы сериализуются SQLite. Разные файлы состояния не защищают друг друга: не запускайте несколько экземпляров с разными файлами на одном счёте. Удаление файла сбрасывает защиту от повторов и историю просадки. Изменение счёта, лота, инструмента или параметров в существующем состоянии вызывает ошибку и требует остановки и проверки прежде чем использовать новое состояние.

Счёт должен содержать только RUB и выбранную акцию. Другие инструменты, заёмные деньги, короткие/заблокированные позиции и чужие открытые заявки вызывают остановку. Пополнения и выводы во время работы не учитываются при расчёте просадки: они исказят максимум капитала.

Все запросы адаптера идут на фиксированный `sandbox-invest-public-api.tbank.ru`. Боевого режима в этой версии нет. 2026-10-05 выполнена попытка подключения с предоставленным токеном песочницы: облачный прокси вернул HTTP 503 с `CERTIFICATE_VERIFY_FAILED` до ответа брокера. Такая же ошибка возникла при запросе без авторизации к прежнему официальному адресу песочницы `sandbox-invest-public-api.tinkoff.ru`. 2026-10-06 подключение выполнено через отдельный бесплатный сервис Render с официальным дополнительным CA: токен принят, рыночные данные получены, выделенный виртуальный счёт создан и пополнен на 100 000 ₽. Проверка плана и шаг с разрешённой отправкой прошли; текущий SMA-сигнал требует удерживать денежный остаток, поэтому заявок не было. Исполнение заявки на сервере пока не проверено. Контракты проверены по [официальному API](https://github.com/RussianInvestments/investAPI), а HTTP-обмен и сценарии исполнения — автоматическими тестами.

Для повторной проверки подключения без создания счёта и заявок:

```bash
python -m moex_bot sandbox-check
```

Команда использует `TINVEST_SANDBOX_TOKEN` или приватный файл `state/.sandbox-token`, сохранённый для текущей сессии с правами 600. Все команды подключения поддерживают `--token-file PATH`; переменная окружения имеет приоритет. Файл токена и каталог `state/` исключены из архива проекта и Git. Сам токен не выводится в отчётах.

Ошибка проверки сертификата на стороне облачного прокси требует исправления доверия сертификату в самой облачной среде или запуска в среде с корректным TLS-доступом. Установка CA только внутри Python не исправляет проверку, которую выполняет внешний прокси. Проверка TLS остаётся включённой; обход через отключение проверки не используется.

### Отдельный сервис проверки подключения

Для запуска вне текущего облачного прокси добавлен `python -m moex_bot.hosted`: HTTP-сервис с отдельным секретом управления `BOT_CONTROL_TOKEN`. Публичная `/` открывает мобильную панель наблюдения, `/health` проверяет работоспособность. При явно заданном `BOT_PUBLIC_MONITOR_ACCOUNT_ID` панель показывает баланс выделенного виртуального счёта, цену и историю SBER, расчётный сигнал и журнал обновлений. Значения поступают из песочницы, без демонстрационных подстановок. Идентификатор счёта, секрет управления и токен брокера не выдаются браузеру.

`GET /api/status` выполняет только чтение. Данные обновляются не чаще раза в 30 секунд, когда открыта страница; холодный запуск показывает загрузку, ошибка сохраняет прежние значения с прежним временем проверки. Сигнал — план стратегии, а журнал отражает проверки, не исполненные сделки. Панель не отправляет заявки. В режиме автоматической песочницы она дополнительно показывает состояние серверного цикла, время последнего/следующего шага и подтверждённый результат. Без явно заданного счёта публикация баланса отключена.

Сборка для Render: `python scripts/install-tbank-ca.py --out state/tbank-ca.pem`. Запуск: `python -m moex_bot.hosted`. Нужны секреты `TINVEST_SANDBOX_TOKEN`, `BOT_CONTROL_TOKEN` и переменная `TINVEST_CA_FILE=/opt/render/project/src/state/tbank-ca.pem`. Официальный корневой сертификат НУЦ проверен по закреплённому SHA-256 и добавляется к системному доверию; проверка имени сервера и TLS остаётся включённой. Источники и отпечаток описаны в [docs/tbank-ca.md](docs/tbank-ca.md).

- `/api/check` с `{}` проверяет авторизацию песочницы; с `{"market_data":true}` также проверяет котировки и свечи.
- `/api/connect` с `{}` создаёт один выделенный виртуальный счёт и пополняет его виртуальными 100 000 ₽. Результаты неопределённой отправки требуют ручной проверки, повторной отправки автоматически нет.
- `/api/step` с `{"submit":false}` проверяет план; `{"submit":true}` разрешает один шаг с виртуальной заявкой. Счёт, тикер и путь состояния заданы сервисом.
- `/api/restore` принимает вручную проверенный прежний cash-only checkpoint и время создания счёта. Разрешено только восстановление известного SBER-счёта с лотом 1 и нетронутыми 100 000 ₽, когда оба локальных состояния отсутствуют. Брокерские счета, остатки, позиции, открытые заявки и операции повторно проверяются. Любая активность или неоднозначность блокирует восстановление; существующая история никогда не перезаписывается. Пустая история операций сама по себе ничего не доказывает: API может запаздывать, поэтому требуется также доверенный прежний отчёт оператора.
- Запись виртуального пополнения может включать RUB FIGI, идентификаторы рублёвого остатка и вложенную запись с нулевыми количеством и ценой. Такой формат допускается только при точном совпадении обоих идентификаторов с проверенным RUB-остатком, времени вложенной записи со временем пополнения и доверенного прежнего отчёта. Операции с акциями и ненулевые сделки не принимаются как пополнение.
- `/api/restore-history` — авторизованная диагностика истории выделенного виртуального счёта: не более 50 записей, без идентификаторов и свободного брокерского текста. Используется для проверки формата виртуального пополнения, без заявок и изменения состояния.
- `/api/auto-resume` с `{}` вручную возобновляет разрешённый серверный цикл после проверки состояния; `/api/auto-stop` с `{}` останавливает цикл текущего процесса. Эти маршруты, как и остальные POST, требуют секрет управления.

По умолчанию автоторговля выключена. `BOT_AUTOTRADE_ENABLED=true` разрешает серверный цикл **только в песочнице**; `BOT_AUTOTRADE_INTERVAL=300` задаёт интервал в секундах после завершения шага. Первый шаг выполняется при запуске процесса, только если полное согласованное состояние счёта уже существует. Счета и пополнения при запуске не создаются. Нет открытой страницы — цикл продолжает работать; нет работающего серверного процесса — проверки и новые заявки прекращаются. Ошибки состояния/чтения останавливают цикл до ручной проверки. Неопределённые заявки сверяются по сохранённому UUID, не отправляются повторно.

Бесплатный Render может засыпать после простоя и терять локальное состояние при перезапуске или повторном развёртывании. Включённая автоторговля на этом тарифе работает **только пока процесс запущен** и не является круглосуточной. Непрерывная работа требует постоянно работающего сервера и постоянного хранилища состояния; платный тариф в текущей сессии не подключён. Панель может читать прежний явно настроенный счёт после перезапуска, но автоматически не восстанавливает торговую историю и просадку. При её потере цикл блокируется; настройка счёта наблюдения также запрещает создавать новый счёт через `/api/connect` вместо потерянного состояния.

Историю из API брокера можно загрузить той же командой с `--source tbank`:

```bash
python -m moex_bot download --source tbank --ticker SBER --from 2024-01-01 --to 2024-12-31 --out data/sber-tbank.csv
```

Если заявка на продажу исполнилась частично, а затем отменена, её свеча считается обработанной. Остаток позиции может сохраниться до нового сигнального дня, в том числе при остановке по просадке. Проверяйте остатки и статус такой заявки вручную в песочнице.

## Торговые правила и границы модели

- При быстрой средней выше медленной бот покупает из денежного остатка, когда позиции нет. В остальных случаях закрывает имеющуюся позицию. Равенство средних означает выход.
- Ограничение 20% применяется к входу с резервом комиссии. Уже открытая позиция удерживается, пока сигнал положительный; её доля может измениться вместе с ценой.
- Бэктест исполняет сигнал закрытия на следующем доступном открытии с ненулевым объёмом. Песочница исполняет рыночной заявкой при очередной проверке после завершённого дня; это может быть позднее открытия и по другой цене.
- При просадке 10% от наблюдаемого максимума новые покупки блокируются до ручного пересмотра состояния, а открытая позиция планируется к продаже. Это порог реакции, **не гарантия предельного убытка**: гэп, закрытие рынка или отказ заявки могут увеличить просадку.
- Незавершённые и будущие свечи не используются. Свечи без объёма исключаются из расчёта SMA и не отменяют ожидающий сигнал бэктеста. Данные должны идти строго по времени, без повторов. Для песочницы есть консервативная проверка давности и будних дней; полноценного календаря торгов нет. Праздники, длительные остановки и торги в выходные требуют отдельного календаря.
- Рыночный объём не моделирует доступную ликвидность и очередь заявок. Оценка размера покупки по последней цене не гарантирует цену исполнения. Песочница проверяет работу API, но не доказывает качество исполнения на реальном рынке.
- Цены не корректируются на дивиденды и сплиты; налоги и доход на денежный остаток не включены. Открытый остаток в финале оценивается по последнему закрытию без комиссии за будущий выход.
- Бенчмарк покупает после такого же периода разогрева, использует такую же начальную долю капитала, лот и расходы входа, затем удерживает позицию без остановки по просадке.

Для оценки пригодности нужны отдельные временные участки, сравнение с бенчмарком с дивидендами и проверка нескольких рыночных режимов. Эта версия не оптимизирует параметры и не подключает реальные деньги.

## Архитектура и проверка

`data.py` получает OHLC из MOEX ISS или CSV; `tbank.py` реализует sandbox REST API. `engine.py` рассчитывает сигналы и бэктест с Decimal. `sandbox.py` сверяет счёт, риск и сохранённую заявку, затем строит план и при `--submit` отправляет виртуальное поручение. `autorun.py` запускает явно разрешённый фоновый цикл через проверяемый обработчик сервиса. `restore.py` допускает только ручное восстановление известного нетронутого виртуального счёта по отчёту и брокерским чтениям. `monitor.py` читает выделенный виртуальный счёт и рассчитывает сигнал для панели `dashboard.py`, без изменения торгового состояния. `cli.py` предоставляет команды и отчёты. `tests/` проверяет расчёты, контракты и повторные запуски.

Критерии первой версии: работа без токена на сохранённых данных, сделки только после сигнала, расходы на обеих сторонах, округление по лотам, неотрицательный баланс, блокировка покупок при просадке, отсутствие повторной заявки после таймаута/перезапуска и отсутствие боевого endpoint.

Дальнейшие этапы: подтвердить sandbox-поведение на вашем токене; выбрать инструменты, капитал и риск; добавить календарь и корпоративные действия; провести независимую проверку стратегии на новых данных. Подключение реального счёта потребует отдельной реализации и проверки.

Текущий сервис: https://moex-sandbox-aleksandr0397.onrender.com . Эта ссылка открывает панель наблюдения за виртуальным счётом. Результат первоначального подключения без секретов сохранён в `reports/sandbox-connection.json`. Автоматическое развёртывание отключено, чтобы обновление документации не сбрасывало локальное состояние бесплатного сервиса. В запросе свечей не передаётся необязательный `limit`: текущий REST-шлюз возвращал HTTP400/code3 при его наличии; источник биржевых свечей задан явно.
